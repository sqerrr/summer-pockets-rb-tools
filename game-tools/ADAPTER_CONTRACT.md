# Контракт адаптера игрового сценария

Пакет не знает текущий формат парсера. Агент должен сохранить существующие инструменты и добавить тонкий адаптер.

## Обязательные операции

```text
parse     игровые файлы → нормализованные сегменты
build     нормализованные сегменты → игровые файлы
smoke     запуск или проверка минимального игрового блока
roundtrip parse → build без изменения текста
```

## Требования к parse

- стабильные ID;
- исходный порядок;
- имя говорящего;
- оригинальный текст;
- все управляющие элементы;
- ссылки на исходный файл и сцену;
- кодировка;
- по возможности голос, спрайт и метки переходов.

## Требования к build

- не изменять непереводимые поля;
- сохранять теги и команды;
- валидировать плейсхолдеры;
- завершаться ненулевым кодом при ошибке;
- писать отчёт о потерянных/лишних ID.

## Round-trip

До массового перевода агент обязан:

1. распарсить оригинал;
2. собрать без изменения текста;
3. сравнить количество и порядок записей;
4. проверить теги;
5. запустить игру;
6. записать результат в `docs/project/parser-audit.md`.

## Файл конфигурации

После проверки заполнить `config/project.yaml`:

```yaml
integration:
  parse_command: "..."
  build_command: "..."
  smoke_test_command: "..."
```
