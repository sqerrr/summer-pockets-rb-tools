# Контракт адаптера игрового сценария

Пакет не знает текущий формат парсера. Агент должен сохранить существующие инструменты и добавить тонкий адаптер.

## Обязательные операции

```text
parse     игровые файлы → нормализованные сегменты
build     нормализованные сегменты → игровые файлы
smoke     запуск или проверка минимального игрового блока
roundtrip parse → build без изменения текста
```

## Требования к parse

- стабильные ID;
- исходный порядок;
- имя говорящего;
- все доступные сопоставленные языковые слоты с явными language tags;
- стабильный `source_id`, не зависящий от байтового смещения и текста;
- хэши исходной записи и каждого языкового payload;
- все управляющие элементы;
- ссылки на исходный файл и сцену;
- кодировка;
- по возможности голос, спрайт и метки переходов.

## Требования к build

- не изменять непереводимые поля;
- принимать канонический прямой Unicode и кодировать его только на build;
- сохранять теги и команды;
- при изменении длины перестраивать все зависимые ссылки профильным
  релокатором; подмена байтов без релокации запрещена;
- валидировать плейсхолдеры;
- завершаться ненулевым кодом при ошибке;
- писать отчёт о потерянных/лишних ID.

## Round-trip

До перевода реального текста агент обязан:

1. распарсить оригинал;
2. собрать без изменения текста;
3. сравнить количество и порядок записей;
4. сравнить порядок и содержимое каждого языкового слота;
5. проверить теги и все ссылки/переходы;
6. запустить игру;
7. записать результат в `docs/project/parser-audit.md`.

## Файл конфигурации

После проверки заполнить `config/project.yaml`:

```yaml
integration:
  parse_command: "..."
  build_command: "..."
  smoke_test_command: "..."
```
