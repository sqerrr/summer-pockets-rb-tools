# Legacy: сборка на SiglusEngine

Не участвует в выпуске. Решением `DEC-0015` переводится и выпускается
Steam-сборка на LucaSystem, активный инструментарий — в `game-tools/`.

Каталог сохранён как независимо проверенный справочный полный цикл: распаковка,
правка, обратная сборка и проверка на запущенной игре, 517 сцен и 409 620 строк
с нулём расхождений. Активный LUCA-профиль уже имеет собственный production
builder, поэтому legacy-код не задаёт текущий процесс и не удаляется только ради
уборки. Его находки лежат в `docs/project/findings-archive.jsonl` и остаются
верными для своей сборки.

## Состав

| Файл | Назначение |
|------|------------|
| `paths.py` | Корень репозитория и пути к игре; читает секцию `game:` конфига |
| `siglus.py` | Формат `Scene.pck`: заголовки, XOR, LZSS, чтение строк |
| `encode_ru.py` | Кодек несущей кириллицы, зеркало `EncodeRussian`/`DecodeRussian` |
| `build_font.py` | Сборка шрифтов из `.orig`: сжатие кириллицы, несущие коды |
| `verify_all.py` | Проверка, что все сцены распаковываются и строки читаются |
| `game.ps1` | Запуск игры, навигация по меню, скриншоты, выход |

### delphi/

Консольные харнессы на рабочем коде `uSiglus.pas`.

- `TestSiglus.dpr` — round-trip на всём пакете;
- `MakeTestPck.dpr` — сборка `Scene.pck` с подменёнными строками;
- `uPaths.pas` — поиск корня репозитория со стороны Delphi;
- `dfm_escape.py` — перевод русских литералов в `.dfm` в `#NNNN`.

Сборка выполняется из этого каталога, иначе относительный путь к `uSiglus.pas`
в `uses` не разрешится:

```bash
cd legacy-siglus/delphi
dcc32 -B -U<delphi>\lib\win32\release -E. -Ndcu TestSiglus.dpr
```

### SPTranslate/

GUI-редактор перевода под `Scene.pck`. `uSiglus.pas` — рабочая реализация
формата, `siglus.py` относительно неё эталонная.

### probes/

Доказательная база находок старой сборки: извлечение ключа, снятие LZSS,
инвариант пересборки, опыты со шрифтами и диапазонами Shift-JIS, разбор
`dat/*.dbs`.

`control_font.py` и `fix_font.py` намеренно портят шрифты — это их работа.
После них шрифты собираются заново через `build_font.py`.

## Ключевое отличие от активной сборки

Здесь кириллица требует **несущей кодировки**: движок отводит символу полную
клетку, если тот представим в Shift-JIS двумя байтами, поэтому русский текст
переносится кодами Latin Extended-A. В LucaSystem этого не нужно — там UTF-16 и
штатный шрифт. Переносить сюда решения активной сборки и обратно нельзя.
