# Технический слой документации

Здесь живёт всё, что описывает игру и инструменты, а не перевод. Переводческая политика остаётся в `docs/translation-spec.md` и соседних файлах.

## Состав

| Файл | Назначение | Когда обновляется |
|------|------------|-------------------|
| `parser-audit.md` | Текущее состояние адаптера: формат, round-trip, ограничения | При изменении понимания формата или результатов проверки |
| `findings.jsonl` | Журнал технических находок и решений | При каждой проверенной находке |
| `../../.agents/skills/vn-engine-siglus/references/siglus-format.md` | Спецификация формата движка | При уточнении формата |

Разделение простое: `parser-audit.md` отвечает на вопрос «что сейчас», `findings.jsonl` — «как мы к этому пришли и почему», спецификация — «как оно устроено».

## Формат находки

Одна строка JSONL, схема — `schemas/finding.schema.json`.

```json
{
  "id": "FND-0001",
  "date": "2026-07-29",
  "area": "scene-pack",
  "kind": "fact",
  "title": "Краткая формулировка",
  "statement": "Что именно установлено.",
  "evidence": "На чём основан вывод, с числами.",
  "method": "Как проверено, чтобы можно было воспроизвести.",
  "artifacts": ["_tools/siglus.py"],
  "status": "verified",
  "supersedes": null
}
```

### Поля

- `id` — сквозной `FND-NNNN`, не переиспользуется.
- `area` — `scene-pack`, `engine`, `font`, `encoding`, `tooling`, `content`.
- `kind`:
  - `fact` — установленное свойство игры или движка;
  - `decision` — принятое техническое решение;
  - `limitation` — известное ограничение, с которым живём.
- `status`:
  - `verified` — проверено воспроизводимым способом;
  - `assumed` — правдоподобно, но не проверено;
  - `refuted` — опровергнуто, запись сохраняется как отрицательный результат.
- `method` — обязателен при `verified`. Без описания способа проверки запись считается `assumed`.
- `supersedes` — ID записи, которую эта заменяет.

## Правила ведения

1. Находка записывается тогда, когда она проверена, а не когда возникла догадка.
2. Опровергнутые гипотезы не удаляются. Ложный след, стоивший времени, экономит его следующему.
3. Утверждение о поведении движка без поля `method` недопустимо: движок неоднократно вёл себя не так, как следует из документации и здравого смысла.
4. Если находка меняет способ сборки, в тот же заход обновляются `parser-audit.md` и спецификация формата.
5. Числа приводятся конкретные. «Работает» — не доказательство, «517 из 517 сцен, 0 расхождений» — доказательство.

## Проверка

```bash
python tools/vnctl.py findings
```

Проверяет JSON, уникальность ID, обязательность `method` при `verified` и ссылки `supersedes`.
