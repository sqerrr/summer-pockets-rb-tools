# Модель данных

## Набор источников

`source/manifest.jsonl` содержит по одной spoiler-safe записи на проверенную
ревизию исходника. Полный текст не коммитится: он воспроизводимо генерируется в
игнорируемом `source/parsed/` и связывается с манифестом хэшем.

Активный набор `SPRB_STEAM_LUCA` содержит слоты `ja`, `en`, `zh-Hans` и
генерируется командой `python game-tools/export_luca_sources.py`.

## Исходная запись

Контракт полного локального каталога определён в
`schemas/source-record.schema.json`. Одна строка представляет либо проверенную
трёхъязычную группу, либо известную служебную нетекстовую форму.

```json
{
  "schema_version": 1,
  "source_set_id": "SPRB_STEAM_LUCA",
  "source_id": "SRC_LUCA_E000001_R000123_G00",
  "classification": "translatable",
  "script_entry": {"index": 0, "id": 1, "name_sha256": "sha256:..."},
  "record": {
    "ordinal": 123,
    "original_offset": 45678,
    "opcode": 36,
    "flag": 3,
    "params_sha256": "sha256:..."
  },
  "slots": [
    {"index": 0, "language": "ja", "encoding": "utf-16le", "speaker": "...", "body_text": "...", "text": "@...@..."},
    {"index": 1, "language": "en", "encoding": "utf-8", "speaker": "...", "body_text": "...", "text": "@...@..."},
    {"index": 2, "language": "zh-Hans", "encoding": "utf-16le", "speaker": "...", "body_text": "...", "text": "@...@..."}
  ]
}
```

`source_id` строится из логического ID PAK-записи и полного ordinal команды,
поэтому рост предыдущих строк и релокация byte offsets его не меняют. Исходное
смещение хранится только как проверочная метаинформация.

Если строка начинается с `@speaker@`, каталог хранит полный `text`, имя
`speaker` и `body_text` отдельно. Имя может отличаться или отсутствовать в
одном из языков, поэтому нормализуется на этапе создания сегментов.

## Сегмент

Одна переводимая реплика или повествовательный блок. Коммитимый сегмент хранит
ссылку на локальный каталог, а не копию официальных исходных текстов.

```json
{
  "id": "SEG_LUCA_E000001_R000123_G00",
  "source_set_id": "SPRB_STEAM_LUCA",
  "source_id": "SRC_LUCA_E000001_R000123_G00",
  "source_hash": "sha256:...",
  "file_id": "LUCA_E000001",
  "scene_id": "LUCA_E000001_SC01",
  "order": 1,
  "speaker": "HAIRI",
  "translation": "…Это ещё что?",
  "status": "draft",
  "flags": [],
  "notes": [],
  "decision_ids": [],
  "metadata": {
    "voice": "voice/file.ogg",
    "tags": []
  }
}
```

`source_hash` равен `record.params_sha256` исходной записи и защищает сразу все
слоты и непрозрачный хвост команды. `vnctl` локально гидратирует поля `source`
и `sources` для индекса и контекста. `translation` всегда хранит прямой
канонический Unicode, а не carrier-коды или байты игрового слота.

Обязательные поля определены в `config/qa-rules.yaml`.

## Сцена

```json
{
  "scene_id": "LUCA_E000001_SC01",
  "file_id": "LUCA_E000001",
  "order": 1,
  "route": "",
  "title_safe": "",
  "segment_ids": ["SEG_LUCA_E000001_R000123_G00"],
  "previous_scene": null,
  "next_scene": "LUCA_E000001_SC02",
  "status": "todo"
}
```

`segment_ids` перечисляет сегменты, но не определяет их идентификаторы: ID
сегмента выводится из `source_id`, а не из сцены. Поэтому переразбиение сцен
меняет только состав этого списка и поле `scene_id` у сегмента, а сами ID
остаются прежними. Схема `COMMON_001_SC01_0001`, где номер сегмента выводился
из сцены, не применяется: она делала любое изменение границ миграцией.

`route` и `title_safe` заполняются только тем, что уже известно игроку.
Название маршрута само по себе может быть спойлером, поэтому по умолчанию поля
пустые.

## Решение

```json
{
  "id": "DEC-0001",

  "scope": "global",
  "segment_ids": [],
  "decision": "...",
  "reason_safe": "...",
  "status": "approved",
  "supersedes": null
}
```

## Внешний референсный фрагмент

Хранится только локально в `references/local/<corpus>/fragments.jsonl`. Это
цельный фрагмент сцены, обычно 3–15 реплик, а не translation memory.

```json
{
  "id": "REF-CLANNAD-SEEN0416-1240-1248",
  "corpus": "clannad-ru",
  "location": {"scene": "SEEN0416", "start": 1240, "end": 1248},
  "lines": [
    {
      "order": 1,
      "speaker": "CHARACTER",
      "source": {"ja": "...", "en": "...", "zh": "..."},
      "translation_ru": "..."
    }
  ],
  "situation": "Краткое описание без лишнего пересказа сюжета.",
  "function": "comic_release",
  "technique": "Как перевод собирает эффект.",
  "selection_reason": "Почему фрагмент полезен.",
  "applicability": "Что можно и нельзя переносить.",
  "status": "raw"
}
```

Поле `source` допускает несколько языков, если доступны параллельные версии.
Без сопоставленного исходника фрагмент может подтверждать только русский ритм и
не получает статус `gold`. Полный контракт —
`schemas/reference-fragment.schema.json`.

Два поля определяют силу фрагмента как доказательства:

- `carrier` — что физически несёт эффект: ритм реплик, повествование, молчание,
  повтор, контраст длины, столкновение регистров. Список открытый. Он полезнее
  жанрового ярлыка: «комедия» и «драма» могут держаться на одном носителе.
- `context_dependency` — читается ли приём в отрыве от истории:
  - `standalone` — понятен без окружения, переносится напрямую;
  - `needs_scene` — нужна окружающая сцена;
  - `needs_history` — работает только на накопленном знании о персонажах.
    Такой фрагмент почти не переносится в другое произведение и не может быть
    единственным основанием наблюдения.

## Запись глоссария

`docs/glossary.yaml`, список записей. Формат приходилось выводить из кода, пока
он не был описан здесь.

```yaml
- id: GLO-0001
  source: 鳥白島            # подстрока исходного текста; по ней идёт отбор
  preferred_ru: Торисиро
  kind: toponym            # personal_name, toponym, speaker_label, term, address
  status: provisional
  notes: "Транскрипция не утверждена, см. OQ-0001."
```

Обязательные поля: `id`, `source`, `preferred_ru`, `status`.

`source` должен встречаться в исходном тексте сцены или в имени говорящего:
отбор в пакет контекста идёт по совпадению подстроки. Имена говорящих лежат
отдельным полем записи, но участвуют в отборе наравне с телом реплики.

Статусы: `provisional` — рабочая форма, решение не принято; `proposed` —
предложено к утверждению; `approved` — утверждено пользователем; `deprecated` —
отозвано.

`provisional` и `proposed` различаются не степенью уверенности, а тем, чего не
хватает: у `provisional` нет принятого решения уровня проекта, например системы
транскрипции; `proposed` — вывод, который можно утвердить как есть.

## Наблюдение о стиле

Промежуточный слой между фрагментом и утверждённым решением. Хранится в
`docs/style-profile.yaml`, в списке `observations`. Текста корпуса не содержит —
только идентификаторы фрагментов, поэтому попадает в Git.

```yaml
observations:
  - id: OBS-0001
    statement: "Формулировка своими словами."
    carrier: [длина реплик, распределение ролей]
    evidence: [REF-CLANNAD-SEEN0415-174-184, REF-CLANNAD-SEEN2417-88-96]
    counter_examples: []
    applicability: "Где приём работает и где перестаёт."
    confidence: low
    status: proposed
```

Правила перехода:

- одно наблюдение из одного фрагмента невозможно: нужно минимум два независимых
  места, желательно из разных маршрутов;
- фрагменты со статусом `needs_history` не образуют наблюдение сами по себе;
- найденный контрпример не удаляет наблюдение, а понижает `confidence` и
  записывается в `counter_examples`;
- наблюдение становится решением в `docs/decisions.jsonl` только после явного
  утверждения пользователем.

## Правила идентификаторов

- ID устойчивы после создания.
- ID не содержат сюжетных спойлеров.
- ID используют ASCII, цифры и `_`/`-`.
- Перемещение сцены не должно автоматически менять ID.
- Если исходник обновился, сохранить ID и обновить `source_hash`.
- Segment ID рекомендуется строить из `source_id`, а не из сцены: перенос
  реплики между логическими сценами не должен переименовывать перевод.
- Вставка или удаление команд в новой ревизии источника требует явной миграции;
  нельзя молча перенумеровывать уже созданные ID.
